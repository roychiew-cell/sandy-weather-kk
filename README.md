# Sandy · Kota Kinabalu weather dashboard

Live page: https://roychiew-cell.github.io/sandy-weather-kk/

- `index.html` — the dashboard. Nothing about the weather is written into the page itself. It has two layers: a **live layer** the browser reads directly (airport METAR via the relay, Open-Meteo "now" and MetMalaysia warnings every 60 s; airport TAF and MetMalaysia forecast every 10 min; MetMalaysia radar every 5 min, frames collected during the session play as a loop) and the **archive layer** from the hourly GitHub job (`data/latest.json`: 7-day models, ensemble, daily comparison, hourly blend), re-read every 15 min. Each card says which layer it is showing and how old the read is; the header shows every source's state (OK / stale / failed, with the last successful read when a check fails). Each live source has its own scheduler: one request in flight, a 15 s deadline that covers the body read too (radar 20 s plus a 10 s decode limit), exponential backoff capped at 30 min and Retry-After (seconds or HTTP-date) honoured on failure; every read is versioned by its start time and carries the source's own data time, so a late or older response never overwrites a newer one. One visible tab per browser polls (coordinated with the Web Locks API, else a 5 s localStorage lease; without a BroadcastChannel every tab polls for itself and the page says so) and shares successes, failures and retry deadlines with the other tabs; a new tab asks the polling tab for a snapshot; a hidden tab releases the role, aborts its pending reads and catches up when shown. The polling tab also re-reads the archive every 15 min and shares it (each tab loads the archive once on its own at start). Checking a feed is not the same as the feed issuing new information (airport 30 min, models hourly, MetMalaysia a few times a day, radar 10 min): a new airport report or warning appears within about a minute of publication, a new TAF or forecast within about 10 min, a new radar image within about 5 min, plus network delay or backoff. Warning status is re-judged every minute; the page re-renders at midnight. Design: professional dark theme, Inter; the sky scene is realistic and data-driven (solar position, cloud cover, wind, rain, lightning), no characters.
- `sandy-metar-relay` (Cloudflare Worker, separate project at `~/Projects/sandy-metar-relay`, URL `https://sandy-metar-relay.trimajasa.workers.dev`): forwards NOAA's METAR/TAF JSON for WBKK with CORS for this site's origin (and localhost:8765 for testing), 60 s edge cache, read-only, no secrets. Routes `/metar?hours=12|24|36|48` and `/taf` only; a browser origin not on the list gets 403, other hours 400; an upstream error is passed through (429 stays 429, else 502) with Retry-After and never cached; headers `X-Upstream-Fetched` and `X-Relay-Served` say when the data was fetched and served. Needed because NOAA's API blocks browser requests. Deploy from that folder with `cf deploy`.
- `scripts/fetch.py` — fetches every source and writes `data/latest.json`. Raw responses, with URL and retrieval time, are archived under `data/raw/`; the last 72 hourly snapshots (3 days) are kept under `data/history/`.
- The sky scene follows the time of day (night, dawn, morning, midday, afternoon, dusk) from the forecast hour and that date's sunrise/sunset; "Play 24 h" runs the next day at 1 h per second, "Play 7 days" runs the week at 6 h per second (168 hourly model values are kept for this).
- `call.json` — Sandy's written forecast for one date (`valid_for`). Written by Claude (Sandy) when Roy asks for a weather update, with the time it was written, the data time it was based on and the radar image looked at (`data/radar/`). After that date the page shows it as an archived forecast and drops the "Today high" tile.
- `.github/workflows/refresh.yml` — every hour (at about :07), on GitHub's servers: fetch → commit `data/` (rebase and retry if the branch moved) → deploy the site to GitHub Pages with `actions/deploy-pages`. A push to the page, call, data, scripts or workflow also deploys (without fetching). GitHub pauses scheduled workflows on repositories with no activity for 60 days; the job's own commits count as activity. GitHub may delay or skip a scheduled run; the page shows a banner when the data is over 3 hours old (an hourly update has been missed).

Sources are chosen for Kota Kinabalu: MetMalaysia forecast (town Tn196 and district Ds554) and warnings (split into dated subsections; a warning counts as covering Kota Kinabalu when it names the city or Sabah's West Coast division without excluding it) via api.data.gov.my; Kota Kinabalu airport (WBKK) observations (48 h) and TAF via aviationweather.gov; the ECMWF ensemble, eight named global models plus the Open-Meteo blend, their 24-hour-ahead runs for the daily comparison, and CAMS air quality via open-meteo.com; MetMalaysia's composite radar image is embedded for reference. The page's last table lists each one with its status in the latest run.

To refresh by hand: run the workflow from the Actions tab. **Do not commit `data/` from a laptop**: the hourly job owns it, and a local commit of older data rebased on top of the job's commit replaces newer public data with older (this happened on 8 Nov 2026). Before committing page or call changes locally, run `git fetch origin && git restore --source=origin/main data` so `data/` stays as the job left it.
