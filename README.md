# Sandy · Kota Kinabalu weather dashboard

Live page: https://roychiew-cell.github.io/sandy-weather-kk/

- `index.html` — the dashboard. Nothing about the weather is written into the page itself. It has two layers: a **live layer** the browser reads directly (airport METAR via the relay, Open-Meteo "now" and MetMalaysia warnings every 60 s; airport TAF and MetMalaysia forecast every 10 min; MetMalaysia radar every 5 min, frames collected during the session play as a loop) and the **archive layer** from the hourly GitHub job (`data/latest.json`: 7-day models, ensemble, daily comparison, hourly blend), re-read every 15 min. Each card says which layer it is showing and how old the read is; the header shows every source's state (OK / stale / failed, with the last successful read when a check fails). Each live source has its own scheduler: one request in flight, a 15 s deadline that covers the body read too (radar 20 s plus a 10 s decode limit), exponential backoff capped at 30 min and Retry-After (seconds or HTTP-date) honoured on failure; every read is versioned by its start time and carries the source's own data time, so a late or older response never overwrites a newer one. One visible tab per browser polls (chosen with the Web Locks API; where Web Locks or BroadcastChannel is missing the channel is closed, every tab polls for itself with its own deadlines, and the page says so in the "next check" pill and the footer) and shares successes, failures (with their own versions) and retry deadlines with the other tabs; a new tab asks the polling tab for a snapshot (live sources, latest radar frame with its fetch time, archive check state); a hidden tab releases the role, aborts its pending reads (including a periodic archive re-read) and catches up when shown. The polling tab also re-reads the archive every 15 min and shares the result or the failure (each tab loads the archive once on its own at start). A feed that answers with older data than already shown is kept out and noted under "Check errors"; results are ordered by version so an equal-version failure never undoes a success and an older success never clears a newer failure. Checking a feed is not the same as the feed issuing new information (airport 30 min, models hourly, MetMalaysia a few times a day, radar 10 min): a new airport report or warning appears within about a minute of publication, a new TAF or forecast within about 10 min, a new radar image within about 5 min, plus network delay or backoff. Warning status is re-judged every minute; the page re-renders at midnight. Design: professional dark theme, Inter; the sky scene is realistic and data-driven (solar position, cloud cover, wind, rain, lightning), no characters.
- `sandy-metar-relay` (Cloudflare Worker, separate project at `~/Projects/sandy-metar-relay`, URL `https://sandy-metar-relay.trimajasa.workers.dev`): forwards NOAA's METAR/TAF JSON for WBKK with CORS for this site's origin (and localhost:8765 for testing), 60 s edge cache, read-only, no secrets. Routes `/metar?hours=12|24|36|48` and `/taf`, each with an optional `ids=` from a fixed list of 25 Malaysian airports (default WBKK); a browser origin not on the list gets 403, other hours or stations 400; an upstream error is passed through (429 stays 429, else 502) with Retry-After and never cached; an upstream timeout (12 s, headers and body) or network error answers 504 with Retry-After 30; headers `X-Upstream-Fetched` and `X-Relay-Served` say when the data was fetched and served. Needed because NOAA's API blocks browser requests. Deploy from that folder with `cf deploy`.
- **Your location card** (8 Nov 2026, Roy's request): "Use my location" asks the browser for the device position once (HTTPS and a tap are required on phones); the coordinates, accuracy, acquisition time and location method are kept only in that browser's localStorage until "Forget" (a restored position is labelled "saved device position"). Coordinates rounded to four decimal places go to Open-Meteo (model forecast for the point, local time zone) and to BigDataCloud's client reverse-geocoder (country, state, Sabah/Sarawak division and district the point is in: this decides whether MetMalaysia covers it, never a distance to a place); api.data.gov.my receives the forecast-location ids of the district (by name, within the state) and the nearest town (within 60 km in the same state); the relay receives the nearest airport's code (within 200 km, inside Malaysia only, and the box says it is the airport's own weather). The page does not send the device position to GitHub (it only fetches its own static files from GitHub Pages). Coverage is inside / outside / unknown (lookup failed) and the card says which. Warnings for the area are judged from the page's selected warning payload with `areaCoverage(text, {state, division, district}, context)`, a closed reading (rewritten 9 Nov 2026 after Astra R22, tightened after R23): the whole text must fit the grammar, i.e. a short weather introduction ("Thunderstorms, heavy rain and strong winds are expected"), "over [the states of]", an area clause, and a strict time tail ("until 9:00 PM; Sunday, 8 November 2026" or "within the period of … until …"); any negation or exclusion wording makes it *undetermined*. The clause is split into entries at bracket depth 0; every entry must be a state name, a known Sabah/Sarawak division, or a name in that state's own vocabulary (built from `places.json` by `scripts/build_vocab.py` into the page and `fetch.py`, with reviewed aliases such as Tanah Tinggi Cameron = Cameron Highlands and registered compound names such as Larut, Matang dan Selama), with at most one bracket list whose names are also known and belong to the right division; a positive needs a valid entry naming the area (and survives unresolved *name* entries but never a structural failure); a state named in the heading counts as owner only when the heading holds nothing but the state and generic warning words. Prose, unknown names, qualifiers such as "excluding", "Eastern Sabah"/"Timur Sabah", empty, nested or unclosed brackets, text after a full stop, an unknown queried district and incomplete area details make the answer *undetermined*, never "not covered". The same code, as `area_coverage` in `fetch.py`, defines `covers_kk`; 161 shared cases in `tests/coverage_cases.json` (real bulletins plus every Astra case) run in both languages (`python3 tests/test_coverage.py`, `node tests/test_coverage.js`), and `node tests/test_assess.js` runs the page's own `assessWarnings` over stubbed bulletins. Round 25 additions: districts, towns, islands and sub-districts are typed separately (a listed smaller region touches only its own parent district, recorded in `PARENTS`; a town or island with unknown containment blocks any exclusion), the queried district must itself be a recognised district before an exclusion, an unfinished state header is fulfilled only by a subordinate entry, a foreign-state entry is inspected whole, a heading with anything beyond the state and generic warning words (or any cancellation wording) makes the reading undetermined, `Larut Matang` is registered, W.P./Wilayah Persekutuan prefixes match across line breaks, and a list wholly outside the known division excludes. Round 24 additions: negation in the heading counts too; free text or an unknown name where a place is expected is a structural failure (capitalisation no longer matters); division lists need a positively known parent (tables completed for Sabah/Sarawak), division names and towns are not districts; places whose bulletin names overlap (Pensiangan/Nabawan, Labuk & Sugut and Paitan/Beluran, Larut, Matang, Selama) never prove exclusion; unfulfilled state headers and foreign-state entries that hide the queried state are structural failures; state names match across line breaks. The location warning box follows the main warnings card (live changes, archive changes, minute re-judging) without a new location request. Model and MetMalaysia boxes show their own read or failure times. Refreshed every 10 min while the tab is visible (separately in each visible tab); "Forget" cancels pending work. `places.json` (built by `scripts/places.py`, run by hand) lists every MetMalaysia forecast location with approximate coordinates: towns and districts geocoded by name with Open-Meteo's geocoder (a few hand-set), states as hand-set centroids; each entry records how it was placed, so the nearest-town match is approximate and the card shows the distance.
- `scripts/fetch.py` — fetches every source and writes `data/latest.json`. Raw responses, with URL and retrieval time, are archived under `data/raw/`; the last 72 hourly snapshots (3 days) are kept under `data/history/`.
- The sky scene follows the time of day (night, dawn, morning, midday, afternoon, dusk) from the forecast hour and that date's sunrise/sunset; "Play 24 h" runs the next day at 1 h per second, "Play 7 days" runs the week at 6 h per second (168 hourly model values are kept for this).
- `call.json` — Sandy's written forecast for one date (`valid_for`). Written by Claude (Sandy) when Roy asks for a weather update, with the time it was written, the data time it was based on and the radar image looked at (`data/radar/`). After that date the page shows it as an archived forecast and drops the "Today high" tile.
- `.github/workflows/refresh.yml` — every hour (at about :07), on GitHub's servers: fetch → commit `data/` (rebase and retry if the branch moved) → deploy the site to GitHub Pages with `actions/deploy-pages`. A push to the page, call, data, scripts or workflow also deploys (without fetching). GitHub pauses scheduled workflows on repositories with no activity for 60 days; the job's own commits count as activity. GitHub may delay or skip a scheduled run; the page shows a banner when the data is over 3 hours old (an hourly update has been missed).

Sources are chosen for Kota Kinabalu: MetMalaysia forecast (town Tn196 and district Ds554) and warnings (split into dated subsections; a warning counts as covering Kota Kinabalu when it names the city or Sabah's West Coast division without excluding it) via api.data.gov.my; Kota Kinabalu airport (WBKK) observations (48 h) and TAF via aviationweather.gov; the ECMWF ensemble, eight named global models plus the Open-Meteo blend, their 24-hour-ahead runs for the daily comparison, and CAMS air quality via open-meteo.com; MetMalaysia's composite radar image is embedded for reference. The page's last table lists each one with its status in the latest run.

To refresh by hand: run the workflow from the Actions tab. **Do not commit `data/` from a laptop**: the hourly job owns it, and a local commit of older data rebased on top of the job's commit replaces newer public data with older (this happened on 8 Nov 2026). Before committing page or call changes locally, run `git fetch origin && git restore --source=origin/main data` so `data/` stays as the job left it.
